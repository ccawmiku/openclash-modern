# OpenClash 管理运行性能讨论

日期：2026-10-03。状态：只读检查与设计讨论，尚未实施优化或完成性能基准。

## 当前范围

保留 OpenClash 全部现有功能，改善配置页面可读性和管理运行性能。继续使用官方 Mihomo 与 MetaCubeXD 的多节点/多策略组体验。

不在本轮改变网络转发、DNS 解析或出口策略，不删除旧平台兼容路径或其他现有功能。DNS/SNI 网络安全观察作为并列独立组件另行讨论；其未来检查任务需要有资源预算，不能持续抓取全部流量影响管理性能。CF 优选等新增功能暂缓。

- /tmp 为 tmpfs，/var 指向 /tmp；/overlay 位于 ext4/eMMC。/var/log 与运行状态已经在内存文件系统路径中。

- /usr/share/openclash/ui 约 6.3 MiB；/etc/openclash 约 106.4 MiB，含内核与其他文件，不能当成全部是需要读取的设置数据。
- 采样时未发现常驻 Ruby 进程。现有 uhttpd、rpcd 和 OpenClash watchdog 的 RSS 很小；不能仅凭安装了 Ruby 就认定它是持续负载来源。
- 生产 status.htm 约 230 KB / 6,016 行，存在 5 秒一次的 status 轮询及多处定时/重试逻辑；已经包含部分 DOM 缓存。模板大小不能直接证明首屏瓶颈。
- 生产 action_refresh_log 每次先执行 wc -l；有更新时分别用 tail/grep 管道筛选日志，输出最多 1,000 行。log_len 虽用于增量展示，但仍会扫描完整文件计数；按行号寻找新增位置也可能扫描旧数据。

## 内存策略

Linux 已有页缓存，热静态资源和二进制通常会被缓存。把整个目录复制到 tmpfs 可能重复保留文件内容；额外收益应通过冷/热访问和块设备 I/O 测量确认。

优先缓存计算结果，避免重复解析、扫描、组装和进程启动。

| 数据 | 拟采用策略 | 保持行为的要求 |
| --- | --- | --- |
| 状态快照、已解析节点/策略索引 | 有界内存缓存 | 修改、外部配置变化与内核重启使缓存失效；界面显示更新时间 |
| 页面尚未保存的编辑 | 浏览器草稿 | 不当作已保存配置，不包含可公开的凭据副本 |
| 日志最新视图与游标 | 增量读取 / 有界内存索引 | 正确处理追加、截断、轮转和清空；保留现有查询/下载与保留语义 |
| 生成中的临时配置与订阅下载 | 现有 /tmp 路径优先 | 校验完成才替换持久配置；保留失败恢复与原子写入 |
| 用户确认保存的设置、订阅地址与规则 | 持久存储 | 成功响应代表已保存；掉电重启后可恢复 |
| 内核可变缓存 | 按格式和恢复要求单独评估 | 不因搬到内存破坏 Fake-IP 映射、重启恢复或升级兼容 |
| 前端静态资源与内核文件 | 原路径 + OS/浏览器缓存 | 优先资源版本哈希、缓存头和按需加载；不先复制整目录 |

tmpfs 大小上限和进程内存都纳入总预算。当前可用内存只是一时快照；没有 swap 时，不可无限堆积日志、连接、节点索引或常驻解析副本。缓存失效、淘汰和降级行为必须明确。

## 优先级

1. 建立可重复基准，区分浏览器、接口、计算和存储延迟。
2. 优化日志读取：使用字节游标与文件身份，或共享的有界增量索引，避免每次全文件计数和多个 shell 管道；文件轮转/截断后返回明确重置标记。
3. 优化请求与渲染：页面可见时刷新，隐藏时暂停非必要任务；初始状态适度合并，版本/说明/静态配置不按秒查询；只更新变化的 DOM，长列表虚拟化、编辑器和图表按需加载。
4. 按测量结果缓存解析与枚举：配置版本区分已保存、待应用与正在运行；缓存键涵盖配置与实际运行周期。需要常驻服务时先比较其额外内存、启动和维护成本。
5. 将后台查询中的可替代 shell 进程改为现有系统接口或直接文件读取；减少重复 Ruby/YAML 解析，仅在确认收益且保持全部语义时替换解析实现。
6. 减少冗余写入和重复应用：不因读取页面提交 UCI，不重复保存相同内容；已确认保存的修改仍持久化。按改动类型应用且不无故重启，不得遗漏必要重载。

WebSocket 不是自动更快：多个页面/浏览器仍可能重复订阅、处理和绘制。流式更新与轮询都应有生命周期管理、背压和有界队列。MetaCubeXD 已有功能先测量并保留，不重写一套重复连接管线。

## 基准与验收

- 页面：打开、切换设置分组、展开长节点/规则列表、查看与搜索日志。
- 写操作：保存设置（不应用）、应用配置、订阅更新分别计时，不把下载耗时当作配置解析成本。
- 后台：无页面访问、单页前台、后台标签、多浏览器访问的 CPU、内存、进程启动与请求量。
- 存储：区分文件系统读取、内存命中、真实块设备读写；重启后冷访问与后续热访问分别测量。不得为生产测试随意 drop_caches。
- 结果：报告典型与较差延迟、长期内存、日志量变化后的表现及 CPU 峰值。功能回归覆盖现有行为，收益需来自相同场景的前后对比。
- 性能优化不得改变网络路由、安全策略或已经保存数据的持久性；缓存返回值与实际运行状态需保持一致。
