# 本机开发与验收记录

更新：2026-10-04（Asia/Shanghai）。本机首版实现和三模块 IPK 已落地；以下是实际完成的验证及其边界。现已在 OpenClash 0.47.097 / iStoreOS 24.10.6 x86/64 路由器安装扩展并保留原设置，见 router-deployment.md。

## 界面与原生功能

现代页面有 8 个主要入口。原版 OpenClash 的控制器、CBI 模型和服务脚本未改写；新增适配器复用原生验证、写入、创建、删除、排序和动作处理。

15 个实际存在的 CBI 模型均可读取，0 个不可读控件。插件设置 160 个控件归为 7 类；节点详情分 5 类；节点策略表的节点、策略组、Provider、批量操作已分开。说明覆盖 509 个“模型＋参数”组合，用途、填写要求、建议分段显示；说明默认展开，开关省略格式、范围、条件，默认值显示“开启/关闭”。除 oixCloud 外，原生字段保留。原控制器的 `other-rules-edit` 路由在该上游版本就缺少对应模型文件，清单明确标记为上游遗留入口。

其余交互已接入：文件编辑与参数比较、上传、覆写文件/订阅、完整订阅高级选项、分享链接、Age 密钥、缓存操作、流媒体测试、面板管理、更新/历史版本/下载来源、备份、运行切换、PAC、网站测试、诊断与日志。新增写接口使用 POST、原生 LuCI CSRF 和 UCI 写权限。原版后台的部分旧动作仍保留其既有实现，因此并非一次全面的后台安全重写。

文件比较按 YAML 参数值进行，保留只读运行配置，不比较注释。比对上限为 512KiB/文件、深度 30、2 万路径、1000 处变化。编辑表单每次只渲染一个字段；字段列表与编辑区内部滚动，记录卡片使用每页六条分页。

本轮界面重排：首页八项实测统计、五分钟流量图和系统资源表，控制与工具默认展开，访问检查与四服务出口查询并列。出口请求同时发起，各自显示结果或失败。设置高层模型为可见导航；DNS 按解析主题、上游用途、记录和详情分层。新增记录使用不写 UCI 的虚拟草稿元数据，提交前完整校验后才调用原生创建和写入；取消不产生记录。详情返回保留原分组、记录和页码。启用开关附着于具体记录，只读状态按文件集中展示；缓存清理等动作只说明用途。贡献者仅首页展示，搜索保留于配置工作区顶部。见 ui-structure.md。

原样嵌入官方 MetaCubeXD，资源独立于前端构建，标准 Mihomo API 直连；没有重写面板 DOM、鉴权、节点接口或资源。内核 v1.19.31 和 v1.19.32 的 `/version`、`/proxies`、`/connections`、HTTPS `/delay` 及原版面板 HTTP 均通过实际测试。两版通过不代表承诺所有未来 API 永远兼容。

## 节点历史

独立 procd 服务顺序调度具体节点，排除策略组与 DIRECT/REJECT 等内建对象。默认每节点 120 秒、单目标 3000ms、最多 32 节点，最多两个 HTTPS 检测目标；失败后才尝试第二目标。可调到最多 64 节点，超额明确提示。节点较多或目标慢时，实际间隔可能延长。

保留最近 240 次探测、7 天小时汇总与最多 64 条状态事件；可调的原始记录上限 360。提供实际请求耗时、中位数/P95/最小最大/平均、相邻成功探测波动、可用率、连续失败、恢复次数、故障时长、导出、立即检测和检查点。前端的曲线按真实延迟绘制，失败/未知断开曲线；7 天共 168 个小时格，缺少探测显示灰色。

一次失败显示首次失败，两次连续失败显示故障。内核关闭、API 不可达或鉴权/监控故障显示未知，并从可用率分母排除；不会自动选路或切节点。身份以节点名称为主；同名换服务器会延续历史，API 未提供稳定端点身份。探测成功不等于所有网站可用，也不证明代理出口可信。

历史主要在 RAM；默认每小时写一次小于 1MiB 的检查点，可关闭。意外掉电最多丢失一小时内的历史；手动检查点可立即保存。记录目录和文件限制访问权限。没有将流量域名、应用正文或节点 API 密钥写进历史。

真实故障验收：停止实验 HTTP 节点，连续两次失败；恢复后记录恢复事件和故障时长。关闭 Mihomo 后状态为未知且失败计数不增加；删除 RAM 快照后从磁盘检查点恢复。实验节点是本地受控 HTTP CONNECT 服务，不是生产 VPS 的线路质量证明。

## DNS 与隐私

独立 `router-privacy` 服务默认阿里 `https://223.5.5.5/dns-query`，备用腾讯 `https://doh.pub/dns-query`。腾讯使用本机固定自举记录 `120.53.53.53` / `1.12.12.12`，证书仍校验 doh.pub。上游地址变化需要更新固定记录；无明文外部自举或失败回退。

独立转发器按顺序使用主/备用，缓存 512，端口 53535。本机 DoH 端口 53531/53532、自举端口 53533；均不得作为对外 DNS 监听端口。DNS 只监听 loopback 与配置的 LAN 接口。nftables 拦截 LAN IPv4/IPv6 TCP/UDP 53，保护本机输出与转发；防护表通过 fw4 include 保留。代理停止不停止这些服务；解析器全部失效时保留阻断规则，可能无法解析但不会回退校园网 DNS。显式关闭 DNS 保护才移除规则。

观察器在配置的 WAN/LAN 获取元数据，解析明文 DNS、HTTP Host、TCP TLS ClientHello SNI、ECH 提出信息，处理部分 TCP 分段；QUIC、未知协议、不完整握手保留未知。结合连接跟踪和可选标准 Mihomo 连接接口确认路径。国内外只读取实际命中的 GeoSite/GeoIP 或 destinationGeoIP；不推断 DIRECT/PROXY 的地域、不猜自定义规则集名称、不另维护网站库。旧 APNIC 分类与安装包数据已移除。规则分类和目标 IP 所在地不等于网站公司的所属国家。

隐私仪表盘显示加密迹象／确认明文／未知比例（按 WAN 记录或捕获字节）、协议分布、后台五分钟快照趋势、DNS/SNI 国内外证据、国外直连、明文 HTTP 与观察覆盖。比例使用当前传感器缓存，闲置五分钟过期，不是严格的滑动五分钟吞吐。LAN/WAN 副本不重复累计，本地 LuCI/SSH 响应不计入比例，缺失趋势样本断线。LAN 明文 DNS 不等于 WAN 泄露；加密 DNS 中的查询域名无法被动分类，无证据不能声称每条国内外查询已安全。国外判定样本为空时风险卡显示未知。DNS 查询不计入网站直连风险。两个监控模块的设置改为独立页面，离开仪表盘停止轮询。具体证据与测试口径见 privacy-dashboard.md。

配置接口范围与能力不是无限的：目前 WAN 观察配置为一个接口，多个出口或不同 IPv6 出口必须另行扩展或逐口核对；LAN 接口需覆盖真实客户端网段。流量卸载、分片、丢包、连接容量及握手遗漏会降低覆盖。启用完整监控可以关闭流量卸载；停用监控会恢复先前设置，这可能影响最高转发速度。页面显示这些限制，不提供“全部流量已安全”的总保证。

抓包元数据和当前连接在 RAM；不落地应用正文，不向外部分类服务上传域名。C 缓存最多 2048 连接，初始 TLS 重组窗口 4096 字节；连接跟踪读取有上限、快照大小有上限。SNI 可读不证明证书校验，ECH 被提出不证明被接受，DoH 不会自动隐藏直连目标 IP/SNI，也不向 DNS 服务商隐藏查询。

真实 DNS 故障验收已通过：IPv4/IPv6 对外 53 请求被接管；关闭 OpenClash 与实验内核仍能解析；拒绝阿里 HTTPS 后使用腾讯；两家都拒绝时解析失败；停独立服务及重载防火墙仍保留保护。测试期间 WAN 抓包没有观测到 TCP/UDP 53 数据包。这是受控场景中的观察结果，不是任意客户端、网络和真实硬件的零泄露证明。

## 管理性能与资源

实验：OpenWrt 24.10.6 x86/64，QEMU/KVM；2 vCPU、1024MiB、无 swap。宿主 VM CPUQuota 150%、MemoryMax 1408MiB、Nice 15；Windows 前端进程树 CPU 12.5%、提交内存 768MiB、Node 堆 384MiB。没有调整全局 WSL 限制。

首屏 JS 约 85.5KB（gzip 34KB）、CSS 41KB（gzip 8.5KB）；设置约 77KB、节点监控约 8.3KB、隐私约 21.1KB、独立监控设置约 8.2KB、YAML 约 96KB，按需加载。路由器无需 Node，也没有引入图表库。首页每五秒读取系统与标准内核 API 数据，最多保留六十个浏览器 RAM 样本；指标快照在路由器 /tmp，读取 API 有两秒和 512KiB 上限，失败时流量未知。隐私服务增加最多六十个 RAM 快照和最多 4096 个短期域名关联，内核接口读取有三秒/2MiB 上限；不新增按域名联网查询。退出页面停止轮询，搜索防抖。日志按描述符和字节游标读取，每次最多 128KiB，浏览器最多 1500 行；无变化请求不重新扫描整个日志。可切换原版翻译/原文，另嵌入原版内核日志与保留调试日志。

约 8MiB 合成日志、热缓存、交替各 30 次真实认证 LuCI HTTP 请求：原接口 P50/P95 54.51/55.86ms，新接口 16.48/17.59ms，中位下降约 70%。这是无新增日志场景的管理接口开销；不能推导整页或网络转发性能。

最终 20.5 秒轻负载采样中，节点历史 RSS 1.75MiB、抓包观察器 1.45MiB、隐私汇总 4.48MiB，三个模块 CPU 各约 0.15%、0.10%、0.44%（单核口径）；独立 DNS 各进程 RSS 总和约 10MiB，Mihomo 46.42MiB。采样前已有累计抓包丢失 601 个，采样期间未增加；不能据此声称启动/页面验收阶段零丢包。

资源采样记录在 `resource-benchmark.json`。RSS 总和会重复计算共享页，且不包含内核 socket 缓存；轻负载结果不代表持续满速抓包。观察器限制 CPU 时间预算，达到预算可能丢包并在页面展示。管理性能改进不意味着关闭卸载后的峰值转发能力提高。

本轮仪表盘更新后另做 20.52 秒轻负载采样，记录在 `privacy-dashboard-resource.json`：隐私汇总 RSS 3.25MiB、单核 CPU 0.536%；观察器 RSS 1.29MiB、CPU 0.097%，采样窗口内未新增抓包丢失。不是严格性能对照或满速证明。移除重复地理数据后，隐私 IPK 约 49.4KB、安装文件约 113.4KB；前端图表仍使用原生 SVG/CSS，无图表库或新增路由器运行时。

## 发布与持续工作

三模块 IPK 已输出，SHA256 在 `artifacts/packages/manifest.json`。原生观察器当前为 x86_64；其他架构需匹配 SDK 编译。未验证 APK、ARM/MIPS、生产硬件与全速网络。

用户最新要求取消每小时任务，应用已确认该任务不存在。本轮完成后保留本机预览，出口/接口覆盖、稳定性、资源占用和交互的进一步优化仅列为待办；所有部署和故障试验只在 localhost 实验机。
