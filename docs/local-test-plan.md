# 本机测试方案

日期：2026-10-03。QEMU/KVM 与 OpenWrt 24.10.6 虚拟机已经运行，并执行了前端、配置读写、日志性能测试。当前结果见 [开发验证记录](development-status.md)。下方保留最初环境检查；其中“未安装/未验证”为实施前状态。

## 本机检查

- Windows，Ryzen 7 5800H，8 核 / 16 线程，约 15.9 GiB 内存。
- Node v24.19.0，pnpm 12.6.0，Git 可用。实际构建仍需按固定源码基线验证工具版本要求。
- 已安装 WSL2 Debian，内核 6.18.33.2-microsoft-standard-WSL2；检查命令已启动该发行版。
- Debian 可见 /dev/kvm，但尚未验证用户访问权限及 QEMU 硬件加速是否实际可用。
- Debian 未找到 qemu-system-x86_64 或 python3。
- Docker CLI 已安装，但当前 Docker Desktop Linux 引擎未运行；不能据此认为 Docker 测试环境已可用。

## 建议路径

用 Windows 浏览器和本机 Web 工程验证页面；用 WSL 中的独立 OpenWrt x86/64 虚拟机验证管理后端。优先调查匹配生产 iStoreOS 的虚拟机镜像与包来源；普通 OpenWrt 24.10 只能提供相近环境，不能视作完全相同的生产系统。

实际采用 1,024MB 内存、2 vCPU，启用 KVM；另用 cgroup 限制 QEMU 进程组 CPU 至 1.5 个逻辑核心时间预算、内存至 1,408MB，并降低优先级。相同资源下对比原版与优化版；限制 vCPU 和内存不能复制 Atom 性能。

不使用桥接网卡，不把电脑设为网关，不接管 Windows DNS、系统代理或主网络。默认使用隔离网络和仅绑定 127.0.0.1 的端口转发；虚拟机中的 DHCP、dnsmasq、fw4 和服务操作只作用于测试网络。外部下载使用受控的构建网络阶段，计时测试采用固定本地数据。

## 三层测试

| 层次 | 测试内容 | 结论范围 |
| --- | --- | --- |
| Windows 浏览器 | 首屏、设置分组、长列表、日志显示、隐藏标签、请求数量与长任务 | 对本机浏览器体验有直接意义；其他设备需另测 |
| Linux 小场景 | 固定日志、YAML/索引缓存、增量读取、解析与扫描成本 | 发现算法与进程开销；不是完整 LuCI 功能验证 |
| OpenWrt 虚拟机 | 原版/优化版 LuCI、UCI、rpcd、uhttpd、配置保存与应用、服务回归 | 验证系统集成和同环境相对差异；不能替代生产设备耗时 |

OpenWrt rootfs 容器可用于部分 CI，但共享宿主内核，服务生命周期和内核模块环境有差异，不作为唯一的路由器运行仿真。SDK/ImageBuilder 负责构建，不等同于完整运行测试环境。

## 测试数据与方法

- 固定原版 OpenClash 基线并记录版本与源码摘要，优化版使用同一环境和相同配置。
- 使用脱敏或生成的测试配置；保留多节点、多策略组、规则、订阅和其他现有功能场景，不将生产密码或订阅凭据写入测试报告。
- 使用不同规模日志和节点列表。日志包含追加、无变化、清空、截断及轮转，检查结果一致性与增量效率。
- 原版与优化版交替重复测量，记录典型/较差延迟、CPU、内存、进程启动次数、请求量和块设备读写。
- 配置保存、生成、应用与服务启动分别计时；网络下载、健康检查延迟单独记录，不混入管理计算性能。
- 冷启动与热访问分开；不通过清理生产系统缓存获得基准。虚拟机恢复快照前停止实例，不克隆同时运行的管理进程。
- 浏览器缓存和 Service Worker 更新流程参与回归，避免旧资源造成假性能结论。

## 后续真实设备验证

本机可以完成主要开发与功能回归。生产硬件上的 CPU、eMMC、内存压力和 iStoreOS 集成差异仍需要最后一次有范围的验证；本机毫秒数或加速比例不得直接宣称是路由器结果。

当前只关注管理运行性能。独立 DNS/SNI 安全观察组件未来需要自己的网络测试环境和验收，不与本轮页面性能基准混合。
