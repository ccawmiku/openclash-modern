# 功能与页面结构

日期：2026-10-03。状态：旧设计提案，已被用户否决。界面预览使用示例数据，不操作路由器。

用户要求采用现成的 Web 开发方式，并使用 MetaCubeXD 保留 Clash 多节点、多策略组切换体验。本文件的自制界面、固定五项导航和单一当前线路示例不作为后续开发要求。当前方案见 [OpenClash 与 MetaCubeXD 的复用方案](reuse-strategy.md)。下面保留原提案供追溯；其中安全和统计要求由当前方案继续承接。

## 设计原则

以用户任务组织页面：判断网络状态、选择线路、管理设备、调整策略、排查维护。一级导航固定为五项，每项有唯一职责；某项设置只有一个编辑入口，其余页面通过链接跳转。

默认提供经过验证的合理配置。高级选项在相关位置折叠，不再增加一整套平行的高级页面。后端仍保持清晰模块边界，避免为了页面少而把所有实现堆在一个文件中。

## 五个一级入口

| 页面 | 日常问题 | 主要内容 | 折叠内容 |
| --- | --- | --- | --- |
| 总览 | 现在是否正常，哪里有问题？ | 当前线路、隐私状态、实时速率、流量趋势、设备排行、异常与连接详情 | 诊断证据详情 |
| 线路 | 用哪条线路，怎样添加或更新？ | 手工节点与订阅统一列表、当前与备用线路、手动/自动选择、质量历史 | 协议参数、订阅转换详情、健康检查参数、CF 优选 |
| 设备 | 哪台设备用了多少，怎样控制？ | 设备身份、在线状态、实时/历史流量、当前连接、策略继承与覆盖 | 地址映射与统计覆盖情况 |
| 策略 | 什么流量怎样走，DNS 怎样保护？ | 默认公网出口、直连例外、域名规则、按设备覆盖、DNS/IPv6 保护 | 原始规则、规则集来源、DNS 端点与引导解析、必要的网络接管参数 |
| 维护 | 怎样诊断、更新和恢复？ | 诊断、内核版本、更新与回滚、备份恢复、近期事件 | 日志、运行配置只读检查、受约束扩展、采样与保留时间 |

页面中可有局部筛选或详情抽屉，但不为每个内核字段创建子页面。

## 总览与 Dashboard

总览就是统一 Dashboard，不另建一套互相重复的管理面板。宽屏与 LuCI 内嵌入口复用同一数据和操作模型。

首屏只突出当前出口、隐私状态、上传/下载与需处理异常。设备排行、趋势和连接列表在下方按需查看，时间范围与设备选择形成局部上下文。

隐私状态区分：策略已配置、保护规则已应用、检测未执行、检测通过、检测失败、检测结果过期。不能因某个开关打开就显示“零泄漏”。通过的检测需要展示时间、范围和证据；无法完成检测显示未知。

连接详情解释源设备、目标域名或 IP、命中策略、实际线路与字节口径。域名未知时显示未知，不推断完整 URL 或客户端进程。查询和图表不得导致无界连接历史或频繁写盘。

## 线路

节点与订阅统一管理。订阅是节点的来源，不是另一套独立配置中心；来源关联、更新状态和节点凭据访问受权限约束。新增时支持粘贴节点链接、订阅地址或手动填写，导入失败明确提示原因。

日常操作只涉及当前线路、备用线路与自动选择范围。协议选定后只显示对应参数；Reality、WS、TUIC 等配置不同时堆在一个表单。列表以可辨认的名称呈现，协议和其他信息作为次要详情。

Cloudflare 优选仅在适用的 CF/CDN 线路详情中出现。展示上次结果、候选、测试路径和切换记录，提供限流、限并发与取消。先验证 TLS、Host、WebSocket 和真实代理连接，达到改善阈值才切换，失败恢复原候选。UI 不暗示优选适用于所有协议。

## 设备与策略

设备页是选择某台设备的入口，设备策略编辑器复用策略页的同一模型。显示设备继承了什么策略、覆盖了什么设置，避免复制一份规则或 YAML。设备识别处理 DHCP 地址变化、IPv6 临时地址与邻居映射；身份不确定时报告统计限制。

严格隐私为默认预设：公网流量通过代理，代理不可用时阻断，校园认证和内网访问作为明确例外。提供分流预设时必须展示其直连范围及可见性影响；原用户的严格隐私要求不能因添加规则或更新订阅而静默放宽。

默认规则入口采用“目标 → 动作”，如域名/设备选择代理、直连或阻断。高级用户可以检查顺序和原始规则。任何重排或覆盖都展示实际优先级，并支持用示例连接解释匹配结果。

DNS 管理先展示意图：公网查询经隧道解析、内网域名使用内网解析、节点引导解析独立处理。底层端点与规则按需展开。IPv6 显示实际接管或阻断状态，不将禁止 AAAA 查询误表示为禁用 IPv6 转发。

## 首次使用与配置应用

首次使用分为：导入线路、确认出口策略与认证例外、检查并应用。自动识别已有系统能力；接管方式只呈现经过验证的推荐方案，具体选择由前期网络与性能测试决定。

操作分为无需应用的即时操作（例如受支持的节点选择）与需要事务的配置修改。需要事务时显示待应用变更及影响，校验后应用。失败恢复已验证组合，管理访问与严格模式保护持续保留。

更新、回滚、诊断等任务展示实际阶段、失败原因与恢复结果，避免一个按钮点下去后只有无限旋转。不能用模拟测试结果充当实际运行状态。

## 第一版范围

必须完成：统一总览、线路导入与切换、设备与基础流量、明确的出口与 DNS/IPv6 策略、故障阻断、诊断、内核升级与完整回滚。

后续增量：长期统计、节点质量评分模型、CF 优选任务与更丰富的规则管理。基础统计先明确覆盖范围；准确性和资源成本验证通过后才扩展历史功能。

首版不建设多个 Dashboard、多内核切换中心、任意订阅脚本执行或逐字段 YAML 表单。

## 结构验收

- 切换线路、查看设备用量、查看连接原因、添加一个域名策略，从一级入口进入后最多两步到达对应操作。
- DNS、规则、订阅和更新各只有一个主编辑入口；其他页面使用上下文跳转。
- 常用流程无需接触 YAML、端口、mark、路由表或内核参数。
- 高级功能可发现、可解释、可恢复；日常用户无需展开它们。
- 初始配置与升级均不能静默放宽严格隐私模式。
- 前端页面数与代码模块数没有一一对应关系，遵循内核适配与管理接口边界。
